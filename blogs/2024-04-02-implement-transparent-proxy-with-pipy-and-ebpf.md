<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*WC4pAyEIxm5bFgz2.jpg" /></figure><h3>Background</h3><h3>Transparent Proxy</h3><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*jhJV_mq2muIW31rE.png" /></figure><p>A <a href="https://en.wikipedia.org/wiki/Proxy_server#Transparent_proxy">transparent proxy</a> is a type of network middleware that can intercept and forward network traffic without the user’s knowledge. Unlike traditional proxies, a transparent proxy does not require specific proxy settings to be configured on the user end. Instead, it intercepts traffic at the network level to provide proxy services. Transparent proxies are commonly used for network management, security policy enforcement, traffic monitoring, and optimization. They can implement functions such as content filtering, cache acceleration, traffic control, and load balancing. Common technologies like TPROXY, NAT, and Divert can be utilized to achieve a transparent proxy.</p><h3>eBPF</h3><p>eBPF is an efficient and flexible kernel technology that allows user-space programs to safely run pre-compiled and restricted programs within the Linux kernel space (i.e., eBPF programs) without changing the kernel source code or loading kernel modules. In recent years, the extensive application of eBPF in networking has made it one of the optional technologies for implementing a transparent proxy.</p><p><a href="https://github.com/flomesh-io/pipy">Pipy</a> has added support for BPF from version 0.99.1, enabling the loading and parsing of BPF programs; the syntax upgrade in version 1.0 has made it more convenient to implement control logic. Today, we will introduce how to implement a simple transparent proxy using Pipy + eBPF.</p><p><strong>Note: All the code mentioned in the article can be found in the Pipy repository: </strong><a href="https://github.com/flomesh-io/pipy/tree/main/samples/bpf/transparent-proxy"><strong>https://github.com/flomesh-io/pipy/tree/main/samples/bpf/transparent-proxy</strong></a><strong>.</strong></p><h3>Quick Start</h3><p>Clone the code.</p><pre>git clone https://github.com/flomesh-io/pipy.git<br />cd samples/bpf/transparent-proxy</pre><p>Compile the BPF program, and you can find the compiled .o file in the directory afterward.</p><pre>make</pre><p>Start the transparent proxy.</p><pre>sudo pipy main.js</pre><p>Once successfully running, the proxy listens on port 18000. Next, let's send a request to test:</p><pre>curl -L bing.com</pre><p>In the proxy’s console, we can find the request and response logs.</p><pre>GET / bing.com<br />  301 Moved Permanently<br />GET / www.bing.com<br />  200 OK</pre><p>Throughout the process, the proxy remains transparent to the client, requiring no proxy configuration.</p><p>Next, we will delve into the implementation of the transparent proxy.</p><h3>Implementation</h3><h3>eBPF Program Design</h3><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*ZLqtYpOieyhUe0sD.png" /></figure><p>Three eBPF programs are used in the implementation, each responsible for different tasks of network interception and forwarding:</p><ul><li><strong>Address Replacement at Connection Establishment</strong>: The first eBPF program, <a href="https://github.com/flomesh-io/pipy/blob/main/samples/bpf/transparent-proxy/transparent-proxy.c#L44">cg_connect4</a>, attaches to the connect system call. When a client attempts to establish a connection with a target server, this program replaces the target's IP address and port with the address and port of the Pipy proxy (usually the local address 127.0.0.1). At the same time, it saves the original target address and port in the struct sock and saves the mapping of the socket's cookie to this sock structure in map_socks for later query and data forwarding.</li><li><strong>Source Address Recording After Connection Success</strong>: The second eBPF program, <a href="https://github.com/flomesh-io/pipy/blob/main/samples/bpf/transparent-proxy/transparent-proxy.c#L69">cg_sock_ops</a>, executes after a connection is successfully established, responsible for recording the source address and port and updating this information in the corresponding sock in map_socks. Additionally, it saves the mapping of the source port and the socket's cookie in map_ports, providing necessary information for subsequent data forwarding.</li><li><strong>Connection and Forwarding Based on Original Destination Information</strong>: The third eBPF program, <a href="https://github.com/flomesh-io/pipy/blob/main/samples/bpf/transparent-proxy/transparent-proxy.c#L87">cg_sock_opt</a>, is triggered when Pipy queries the original destination information through getsockopt. This program uses the source port to retrieve the socket's cookie from map_ports, and then from map_socks to get the original destination information, then establishes a connection with the original target and forwards the client's request.</li></ul><h3>eBPF Program Loading</h3><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*T7G5BQ2nnehZ4-ai.png" /></figure><p>With the support for BPF in Pipy, developers can directly handle BPF programs in PipyJS, meaning operations on BPF no longer depend on tools like bpftool or require development with other language libraries like BCC, GoBPF. This integration offers significant convenience and flexibility, allowing the eBPF control plane and proxy logic to run in the same process, simplifying deployment and management.</p><p>Here is a key code explanation for operating eBPF in Pipy, based on the example in the <a href="https://github.com/flomesh-io/pipy/blob/main/samples/bpf/transparent-proxy/main.js">main.js</a> file:</p><p>In PipyJS, you can use the bpf module's API to load and operate eBPF programs. Here's a typical usage:</p><p>Use the bpf.object() API to load a compiled eBPF program object; this step requires specifying the path of the eBPF program file. Then, use the load() method to load the eBPF program into the kernel. This step is necessary because only after being loaded into the kernel can the eBPF program start working.</p><pre>var obj = bpf.object(pipy.load('transparent-proxy.o'))<br />var progCgConnect4 = obj.programs.find(p =&gt; p.name === 'cg_connect4').load('BPF_PROG_TYPE_CGROUP_SOCK_ADDR', 'BPF_CGROUP_INET4_CONNECT')<br />var progCgSockOps = obj.programs.find(p =&gt; p.name === 'cg_sock_ops').load('BPF_PROG_TYPE_SOCK_OPS')<br />var progCgSockOpt = obj.programs.find(p =&gt; p.name === 'cg_sock_opt').load('BPF_PROG_TYPE_CGROUP_SOCKOPT', 'BPF_CGROUP_GETSOCKOPT')</pre><p>Write the configuration into the Map map_config, where the configuration is the port the proxy listens on.</p><pre>obj.maps.find(m =&gt; m.name === 'map_config').update(<br />  { i: 0 }, {<br />    proxy_port: PROXY_PORT,<br />    pipy_cgroup_id: bpf.cgroup(CGRP_PIPY)<br />  }<br />)</pre><p>Then you can attach the eBPF programs to the specified hooks.</p><pre>bpf.attach('BPF_CGROUP_INET4_CONNECT', progCgConnect4.fd, CGRP)<br />bpf.attach('BPF_CGROUP_SOCK_OPS', progCgSockOps.fd, CGRP)<br />bpf.attach('BPF_CGROUP_GETSOCKOPT', progCgSockOpt.fd, CGRP)</pre><p>Also, don’t forget to clean up the eBPF programs when the proxy exits.</p><pre>pipy.exit(<br />  function() {<br />    bpf.detach('BPF_CGROUP_INET4_CONNECT', progCgConnect4.fd, CGRP)<br />    bpf.detach('BPF_CGROUP_SOCK_OPS', progCgSockOps.fd, CGRP)<br />    bpf.detach('BPF_CGROUP_GETSOCKOPT', progCgSockOpt.fd, CGRP)<br />    os.write(`${CGRP}/cgroup.procs`, pipy.pid.toString())<br />    os.rmdir(CGRP_PIPY)<br />  }<br />)</pre><p>After completing the eBPF control plane logic, the next step is the implementation of proxy forwarding.</p><p>Use the Pipeline API onStart to get the client's original destination information via socket.getRawOption after successfully connecting with the client. This action will trigger the third eBPF program mentioned above.</p><pre>pipy.listen(PROXY_PORT, $=&gt;$<br />  .onStart(<br />    function (ib) {<br />      var od = new Data<br />      ib.socket.getRawOption(SOL_IP, SO_ORIGINAL_DST, od)<br />      var sa = sockaddr_in.decode(od)<br />      var addr = sa.sin_addr<br />      var port = sa.sin_port<br />      $targetAddr = addr.join('.')<br />      $targetPort = (port[0] &lt;&lt; 8) | port[1]<br />    }<br />  )<br />  ...</pre><h3>Conclusion</h3><p>This simple example of a transparent proxy effectively demonstrates the combined power of Pipy and eBPF, two programmable technologies. Although there is a gap from achieving an ideal transparent proxy — for example, the target server sees the proxy’s address instead of the client’s real IP, which is crucial for scenarios requiring recording of the real client IP — with eBPF technology, we can still achieve the goal. The approach involves using eBPF programs to adjust the source address and port in the network packets forwarded by Pipy and modifying the destination address and port in the returning packets to achieve transparency to the target server.</p><p>Compared to other technical solutions, eBPF provides unmatched flexibility and programmability in implementing transparent proxies. It not only reduces dependence on kernel network stack processing but also significantly enhances performance.</p><p>By integrating operations of eBPF programs into Pipy, we can achieve seamless integration of application-layer and kernel-layer programmable functionalities, further strengthening the practicality and efficiency of this solution.</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=b97bc58be308" width="1" /><hr /><p><a href="https://blog.flomesh.io/implement-transparent-proxy-with-pipy-and-ebpf-b97bc58be308">Implement Transparent Proxy with Pipy and eBPF</a> was originally published in <a href="https://blog.flomesh.io">Flomesh</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
