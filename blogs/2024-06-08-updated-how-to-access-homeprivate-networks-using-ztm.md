<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*xePBR1ryZDLalJ1SuwFalQ.jpeg" /><figcaption>Photo by Nadine Wuchenauer from Pexels</figcaption></figure><p>In the <a href="https://blog.flomesh.io/how-to-use-ztm-to-access-home-private-networks-8848efb1f935">previous article</a>, we briefly introduced the features and capabilities of <a href="https://github.com/flomesh-io/ztm">ZTM</a> and demonstrated step-by-step how to use ZTM to access home networks without a fixed public IP.</p><blockquote><em>ZTM (Zero Trust Mesh) is an open-source network infrastructure software for running decentralized networks. It is built on HTTP/2 tunnels and can operate on any type of IP network, such as LANs, containerized networks, and the internet.</em></blockquote><p>With the release of ZTM <a href="https://github.com/flomesh-io/ztm/releases/tag/v0.0.3">0.0.3</a>, ease of use has significantly improved, such as running components in the background without relying on other tools like screen.</p><p>For more information about ZTM and the background of this article, please refer to the <a href="https://blog.flomesh.io/how-to-use-ztm-to-access-home-private-networks-8848efb1f935">previous article</a>.</p><h3>Demonstration</h3><p>First, let’s introduce today’s demonstration environment:</p><ul><li><strong>Home/Private Network</strong>: This network includes my HomeLab virtual machines and Windows devices without a fixed public IP.</li><li><strong>Public Cloud Network</strong>: A low-spec cloud host with 1 core CPU, 1GB RAM, and 5Mbps bandwidth, at a very low cost.</li><li><strong>Public Network</strong>: Mobile network or public Wi-Fi in cafes/malls, which I often use.</li></ul><p>During the demonstration, I will switch between these three environments to configure ZTM. Don’t worry; this configuration is a one-time setup, not a regular task.</p><h3>Architecture</h3><p>Below is the architecture diagram of the demonstration environment:</p><ul><li>The <strong>left</strong> represents the home network with web services running on the HomeLab and a Windows PC, along with a running ZTM Agent.</li><li>The <strong>middle</strong> represents the public cloud network with a fixed public IP, where ZTM Hub is deployed to provide access relay and other functions. Additionally, the ZTM CA service issues certificates for the Hub and Agents, used for encrypted data transmission, identity authentication, and access authorization.</li><li>The <strong>right</strong> represents the public network, where my MacBook is used to access services and devices in the home network, also running the ZTM Agent.</li></ul><p>Agents on both sides establish encrypted secure reverse tunnels to the cloud host, so the networks they are in do not need a fixed public IP.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*42ZAxvAh5XuJ3e-d.png" /></figure><p>Let’s get started!</p><h3>Installing ZTM</h3><p>First, we will install ZTM on the cloud host, deploying the CA service and Hub. Download and install the executable file for the Linux platform from the <a href="https://github.com/flomesh-io/ztm/releases">release page</a>.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.3/ztm-aio-v0.0.3-generic_linux-x86_64.tar.gz | tar -zxf -<br />sudo cp bin/ztm /usr/local/bin/ztm</pre><h3>Starting the CA Service</h3><p>Start the ZTM CA service with the following command. This command creates a system service, with the CA service listening on port 9999 by default. You can change the port by modifying the /etc/systemd/system/ztm-ca.service configuration (note: after modification, execute systemctl daemon-reload to reload the configuration and restart the service with systemctl restart ztm-ca). Alternatively, you can change the port during startup with the --listen parameter.</p><pre>sudo ztm start ca --listen 127.0.0.1:9999</pre><h3>Starting the Hub</h3><p>Execute the command to start the Hub service, which listens on port 8888 by default. Once started, the Hub will obtain certificates from the CA service.</p><pre>sudo ztm start hub</pre><p>Let’s begin with a simple service access.</p><h3>Scenario 1: Accessing Services in the Home Network</h3><h3>Home Network Access</h3><p>On the cloud host, generate a certificate for the home device through the CA service: specify the Agent name home and the Hub address 43.155.26.189:8888, and save the generated content in home.json. This file contains the Hub address, the certificate and key allocated to the Agent, and the CA certificate.</p><pre>ztm invite home --bootstrap 43.155.26.189:8888 --output &gt; home.json</pre><p>On the device in the home network, start the Agent; in this case, it’s an Ubuntu virtual machine. Install ZTM first as described in the <a href="https://markdown-to-medium.surge.sh/#%E5%AE%89%E8%A3%85-ZTM">Installing ZTM</a> section.</p><p>After installing ZTM, start the Agent with the following command. It listens on 127.0.0.1:7777 by default.</p><pre>sudo ztm start agent</pre><p>After starting the Agent, use the previously generated home.json to connect to the Hub.</p><pre>ztm join my-hub --as home --permit home.json</pre><p>Check the connection status. A status of <strong>Connected</strong> indicates that the Agent successfully connected to the Hub.</p><pre>ztm get mesh<br />NAME    JOINED AS  USER  HUBS                 STATUS<br />my-hub  home       home  43.155.26.189:8888  Connected</pre><p>Use ztm get endpoint to view endpoint information, such as IP addresses, ports, and statuses. At this point, only one Agent is connected to the Hub, so only one record is displayed.</p><pre>NAME          USER  IP             PORT   STATUS<br />home (local)  home  103.116.72.46  53141  Online</pre><p>Next, register the home network service to the Mesh. Here, we simulate a simple web service with Pipy: pipy 'pipy.listen(8080, $=&gt;$.serveHTTP(new Message(&quot;hi&quot;)))'.</p><p>When registering a service, provide the following information:</p><ul><li>Service name: format protocol/NAME, currently supports tcp and udp protocols.</li><li>Host address</li><li>Port</li></ul><pre>ztm create service tcp/hi --host 127.0.0.1 --port 8080</pre><p>View the service information.</p><pre>ztm get service<br />NAME    ENDPOINTS<br />tcp/hi  1</pre><p>At this point, we have completed connecting the home network to the Mesh and registering the service.</p><p>Next, let’s try accessing the service in the home network from an external network.</p><h3>External Network Access</h3><p>Now, connect my computer to an <strong>external network</strong> (using a mobile hotspot for testing).</p><p>On the <strong>cloud host</strong>, generate a certificate for my computer through the CA service.</p><pre>ztm invite macbook --bootstrap 43.155.26.189:8888 --output &gt; macbook.json</pre><p>Download and install the executable file for the macOS platform from the <a href="https://github.com/flomesh-io/ztm/releases">release page</a>.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.3/ztm-aio-v0.0.3-macos-arm64.tar.gz | tar -zxf -<br />sudo cp bin/ztm /usr/local/bin/ztm</pre><p>Start the Agent and use the configuration macbook.json to join the Hub network.</p><pre>sudo ztm start agent<br />ztm join my-hub --as macbook --permit macbook.json</pre><p>Check the status; <strong>Connected</strong> indicates successful network access.</p><pre>ztm get mesh<br />NAME            JOINED AS  USER     HUBS                 STATUS<br />my-hub          macbook    macbook  43.155.26.189:8888  Connected</pre><p>At this point, viewing endpoint information shows two endpoints: one is the current device (displayed as local), and the other is the home Agent connected earlier.</p><pre>ztm get endpoint<br />NAME             USER     IP             PORT   STATUS<br />home             home     103.116.72.46  53141  Online<br />macbook (local)  macbook  45.62.167.232  32897  Online</pre><p>Viewing the service shows the hi service registered in the home network.</p><pre>ztm get service<br />NAME    ENDPOINTS<br />tcp/hi  1</pre><p>To access the hi service from the local machine, map the service to a local port. Provide the following information:</p><ul><li>Port name format host/protocol/port, here it is 127.0.0.1/tcp/18080</li><li>The service name to map</li></ul><pre>ztm create port 127.0.0.1/tcp/18080 --service tcp/hi</pre><p>You can also view port information from the command line.</p><pre>ztm get port<br />NAME                 ENDPOINT  SERVICE<br />127.0.0.1/tcp/18080  macbook   tcp/hi</pre><h3>Testing</h3><p>Accessing 127.0.0.1:18080 on the current device shows a successful return.</p><pre>curl -i 127.0.0.1:18080<br />HTTP/1.1 200 OK<br />content-length: 2<br />connection: keep-alive</pre><pre>hi</pre><p>Next, let’s try accessing a Windows device in the home network remotely.</p><h3>Scenario 2: Accessing Remote Windows Desktop</h3><p>In the home network, there is a Windows device with IP address 192.168.11.247 and remote desktop login enabled.</p><h3>Registering Windows Remote Login Service</h3><p>Connect to the <strong>home network</strong>. On the home network Agent, register another service RDP and fill in the Windows device's IP and port (default is 3389).</p><pre>ztm create service tcp/RDP --host 192.168.11.247 --port 3389</pre><p>Now our home network exposes two services: hi and RDP.</p><pre>ztm get service<br />NAME     ENDPOINTS<br />tcp/hi   1<br />tcp/RDP  1</pre><h3>macOS</h3><p>Switch back to the external network. Use the command ztm get service to see the RDP service registered in the home network.</p><p>Next, map the RDP service to the local 127.0.0.1:13389.</p><pre>ztm create port 127.0.0.1/tcp/13389 --service tcp/RDP</pre><p>Mapping completed.</p><pre>ztm get port -m my-hub<br />NAME                 ENDPOINT  SERVICE<br />127.0.0.1/tcp/18080  macbook   tcp/hi<br />127.0.0.1/tcp/13389  macbook   tcp/RDP</pre><h3>Testing</h3><p>This time, use <strong>Microsoft Remote Desktop</strong> on macOS to access the remote desktop.</p><p>Add a PC with the address 127.0.0.1:13389 and the Windows device's login credentials.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*M1ftW_sJFFTXWHAO.png" /></figure><p>After logging in, you can remotely operate the Windows device.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*ioagWOfq_UgH6ZVi.png" /></figure><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*ZykwdPqLuV-_RqJT.png" /></figure><h3>Summary</h3><p>Building on the previous article, this demonstration showed how to configure ZTM components and networks via command line. All operations can be completed in the terminal, thanks to the optimizations brought by ZTM version 0.0.3.</p><p>Stay tuned for future ZTM upgrades, as we will provide more features and scenario demonstrations.</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=19f27dc8692f" width="1" /><hr /><p><a href="https://blog.flomesh.io/updated-how-to-access-home-private-networks-using-ztm-19f27dc8692f">Updated: How to Access Home/Private Networks Using ZTM</a> was originally published in <a href="https://blog.flomesh.io">Flomesh</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
