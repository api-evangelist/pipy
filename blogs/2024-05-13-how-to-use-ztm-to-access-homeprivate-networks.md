<p>In our work and daily life, we often need to remotely access home or private networks, whether it is due to the requirements of remote work, monitoring smart home devices, or enterprises accessing internal resources across regions. Due to cost considerations and restrictions imposed by network operators, these private networks often do not have a public IP assigned. While this practice reduces the risk of network attacks and enhances privacy protection, it also restricts the ability to directly access these internal resources from the Internet, which can be inconvenient.</p><p>Of course, there are solutions to this problem, such as internal network penetration and VPNs. However, these solutions either have complex network configurations or are expensive, and they increase the risk of being attacked. The performance of data transmission may also be affected when the service provider’s servers are far from the user.</p><p>Here, I will introduce another low-cost, high-security, and high-performance solution: <a href="https://github.com/flomesh-io/ztm">ZTM</a>.</p><h3>About ZTM</h3><p>ZTM (Zero Trust Mesh) is an open-source network infrastructure software used to run decentralized networks. It is built on HTTP/2 tunnels and can run on any type of IP network, such as local area networks, containerized networks, and the Internet.</p><p>ZTM lays the foundation for building decentralized applications, providing a range of core features, including:</p><ul><li>Network connections across internet gateways and firewalls</li><li>TLS encrypted transmission channels</li><li>Certificate-based authentication and access control</li><li>Service discovery and load balancing</li></ul><p>ZTM can be used in various environments, from connecting home and workplace 2-node personal networks to connecting global offices and branches of 10,000-node enterprise networks. Applications that can leverage ZTM include:</p><ul><li>Remotely accessing your home computer from anywhere in the world</li><li>Sharing documents, pictures, and videos with others without relying on large tech social networking platforms</li><li>Private and secure P2P chat or voice/video conferencing without fear of eavesdropping</li></ul><p>ZTM supports multiple CPU architectures, such as x86, ARM, MIPS, RISC-V, LoongArch, etc., as well as various operating systems, such as Linux, Windows, macOS, FreeBSD, Android.</p><p>To learn more about ZTM, you can visit <a href="https://github.com/flomesh-io/ztm/wiki#ztm-zero-trust-mesh">ZTM Introduction Documentation</a> and <a href="https://github.com/flomesh-io/ztm/wiki/Why,-what-and-how-ZTM">Why, what and how ZTM</a>.</p><p>Next, I will guide you on how to use ZTM to securely and conveniently access private networks.</p><h3>Demonstration</h3><p>First, let me introduce today’s demonstration environment:</p><ul><li>Home/Private Network: This network includes my HomeLab virtual machine and a Windows device, with no fixed public IP.</li><li>Public Cloud Network: A very low-spec cloud host: 1 core CPU, 1G memory, 5m bandwidth, at a very low cost.</li><li>Public Network: Mobile network or public Wi-Fi at cafes/malls, which I often use.</li></ul><p>In the following demonstration, I will switch between these three environments to configure ZTM. Don’t worry, this configuration is one-time, not the norm.</p><h3>Architecture</h3><p>Below is the architecture diagram of the entire demonstration environment:</p><ul><li>On the left, the home network, with a web service running on HomeLab and a Windows PC, as well as the running ZTM Agent.</li><li>In the middle, the public cloud network: With a fixed public IP, this hosts the ZTM Hub, providing access relay functions; additionally, there is a ZTM CA service, issuing certificates for the Hub and Agent, which are used for data encryption transmission, identity authentication, and access authorization.</li><li>On the right, the public network: My MacBook, used to access services and devices in the home network, also running the ZTM Agent.</li></ul><p>The Agents on both sides establish secure reverse tunnels with the public cloud host, so their networks do not need a fixed public IP.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*Qau1pnSEuxw-8iEB.png" /></figure><p>Let’s get started!</p><h3>Installing ZTM</h3><p>First, we install ZTM on the virtual machine in the public cloud, deploying the CA service and Hub. Go to the <a href="https://github.com/flomesh-io/ztm/releases">download page</a> to download the installation executable for the Linux platform.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.2/pipy-ztm-v0.0.2-ubuntu-x64.gz | gzip -cd - &gt; pipy<br />chmod +x pipy</pre><h3>Starting the CA Service</h3><p>Start the CA service in a new session, specifying its listening interface on the loopback network card at 9999 with the parameter --listen.</p><pre>screen -S ca-svc<br />./pipy repo://ztm/ca --args --listen=127.0.0.1:9999</pre><p>First, issue a CA certificate through the CA service.</p><pre>curl http://localhost:9999/api/certificates/ca | tee ~/ca.crt</pre><h3>Starting the Hub</h3><p>Run the following command in a new session to start the Hub. The Hub defaults to listening on 0.0.0.0:8888, which can be modified like the CA service above with the parameter --listen; also, the Hub defaults to connecting to the localhost:8888 service to manage certificates, which can also be adjusted with the parameter --ca. <strong>Note: If the Hub is running in a virtual machine, you need to specify the public IP and port of the virtual machine with the </strong><strong>--name parameter!</strong></p><pre>screen -S ca-svc<br />./pipy repo://ztm/hub</pre><p>Let’s start with a simple service access.</p><h3>Scenario 1: Accessing Services in the Home Network</h3><h3>Home Network Access</h3><p>On the cloud host, generate certificates for home devices through the CA service.</p><pre># home key<br />curl -s http://localhost:9999/api/certificates/home -X POST | tee home.key<br /># home cert<br />curl -s http://localhost:9999/api/certificates/home | tee home.crt</pre><p>Start the Agent on the device in the home network, here it’s an Ubuntu virtual machine. First, install ZTM.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.2/pipy-ztm-v0.0.2-ubuntu-x64.gz | gzip -cd - &gt; pipy<br />chmod +x pipy</pre><p>The Agent defaults to listening on 127.0.0.1:7777, which can be modified with the parameter --listen.</p><pre>screen -S agent<br />./pipy repo://ztm/agent</pre><p>After starting, you can open the graphical interface in the browser (at this point, my computer is connected to the home network for configuration).</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*uK1j3z3w3qgspWnz.png" /></figure><p>In the Mesh window, click <strong>Join</strong> to configure the Mesh network. Here, you need to provide the name of the Mesh network addo, the name of the Agent home, the CA certificate, the certificate and key generated for the Agent, and most importantly, the address of the Hub 43.155.26.189:8888. <strong>Note: In the current version, you need to press Enter after entering the address to confirm!</strong></p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*EYv3TUyhfgeprKQ5.png" /></figure><p>After saving, you can see the Mesh we’ve joined in the Mesh window. The status <strong>Connected</strong> indicates a successful connection to the Hub and successful network access.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*BkVHr6qgAWA2Y55W.png" /></figure><p>Also, in the Endpoints window, you can see the current endpoint information.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*nT0bSI-LAUo7ny-N.png" /></figure><p>Next, we’ll register the home network’s services in the Mesh. Here, we’ve simulated a simple web service with Pipy pipy 'pipy.listen(8080, $=&gt;$.serveHTTP(new Message(&quot;hi&quot;)))'.</p><p>When registering the service, you need to provide the name of the service, as well as the access address and port: Hi, 198.19.249.153 (home network subnet), and 8080.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*dsXb6tti5Emnb6qa.png" /></figure><p>After saving successfully, you can find the service from the Service page.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*NaFm9bjNm1q_-920.png" /></figure><p>At this point, we have completed the access of the home network to the Mesh and the registration of services.</p><p>Next, we will try to access the services in the home network from the external network.</p><h3>External Network Access</h3><p>Now, connect my computer</p><p>to the <strong>external network</strong> (testing using a mobile hotspot).</p><p>On the cloud host, generate certificates for home devices through the CA service.</p><pre># macbook key<br />curl -s http://localhost:9999/api/certificates/macbook -X POST | tee macbook.key<br /># macbook cert<br />curl -s http://localhost:9999/api/certificates/macbook | tee macbook.crt</pre><p>Go to the <a href="https://github.com/flomesh-io/ztm/releases">download page</a> to download and install the executable for the macOS platform.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.2/pipy-ztm-v0.0.2-macos-x64.zip -o pipy-ztm.zip<br />unzip -p pipy-ztm.zip  &gt; pipy<br />chmod +x pipy</pre><p>Start the Agent and specify its listening on 127.0.0.1:5555.</p><pre>./pipy repo://ztm/agent --args --listen=127.0.0.1:5555</pre><p>Likewise, you need to connect the external network to the Mesh network, similar to the home network’s access.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*ac8anI5H78qBT3Mh.png" /></figure><p>The status <strong>Connected</strong> indicates successful network access.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*3tTdEFmsm1LpNPVY.png" /></figure><p>In the Endpoints window, you can see the current endpoint, as well as the endpoint accessed by the home network. They are distinguished by the labels Local and Remote.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*EEeJGXAJuEOiKPoZ.png" /></figure><p>In the Service window, you can see the registered service Hi.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*A4a6M8VY7tizamdK.png" /></figure><p>Clicking the button on the service card takes you to the service connection interface. Here, you can <strong>map the service registered by the remote endpoint to local</strong>. For example, here we map the service Hi to local 127.0.0.1:18080.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*vjJ5k3_lB7xCI_A0.png" /></figure><p>The Ports page can see the successfully mapped port (status is green).</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*pHxwyuHu7akrtXrG.png" /></figure><p>After completing the service mapping, you can test it.</p><h3>Test</h3><p>Access 127.0.0.1:18080 on the current device to see a successful return.</p><pre>curl -i 127.0.0.1:18080<br />HTTP/1.1 200 OK<br />content-length: 2<br />connection: keep-alive</pre><pre>hi</pre><p>Next, we will attempt to remotely access a Windows device within the home network.</p><h3>Scenario 2: Accessing Remote Windows Desktop</h3><p>In the home network, there is a Windows device with the IP address 192.168.11.184 and remote desktop login enabled.</p><h3>Register Windows Remote Login Service</h3><p>Let’s switch back to the home network. On the home network’s Agent, register another service RDP and fill in the Windows device's IP and port (default 3389).</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*bbFTSGxkNdPRQeYd.png" /></figure><p>After saving, you can see the newly registered service in the Service window.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*CE9gr4xDDcfdIRL7.png" /></figure><h3>macOS</h3><p>Let’s switch back to the external network, where you can also see the RDP service registered by the home network in the service window.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*9-_J9aZ1QzDD6j83.png" /></figure><p>The same operation, map the RDP service to local 127.0.0.1:13389.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*tTzo_5ZbOeOc5TzG.png" /></figure><p>Mapping completed.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*kEg-2rQkRSdnrkK5.png" /></figure><h3>Test</h3><p>This time, we use the <strong>Microsoft Remote Desktop</strong> software on the macOS platform to access the remote desktop.</p><p>Add a PC with the address 127.0.0.1:13389, and the account is the login account of the Windows device.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*40_7zkr2ZK9LuLse.png" /></figure><p>After logging in, you can remotely operate the Windows device.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*PH_IVUHUktQlQ1IX.png" /></figure><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*x3gCEGPsTTRIWMWI.png" /></figure><h3>Summary</h3><p>In this article, we briefly introduced the features and characteristics of ZTM, and step by step demonstrated how to use ZTM to access a home network without a fixed public IP.</p><p>ZTM’s decentralized network, built on HTTP/2 tunnels, fully embodies the characteristics represented by Z: Zero privilege, zero firewall settings, zero routing, zero system settings, zero exposure. Smaller exposure surface, more secure, lower cost, more convenient management.</p><p>In the future, we will introduce the working principles of ZTM and more usage scenarios through more articles, so stay tuned.
