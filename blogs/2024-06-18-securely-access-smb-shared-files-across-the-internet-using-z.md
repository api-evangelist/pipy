<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*wMb6tTVx-udc4bhD.jpg" /></figure><h3>Background</h3><p>SMB (Server Message Block) is a network file-sharing protocol used for sharing files, printers, and other resources between computers on a network. SMB is primarily used in local area networks (LANs), providing high performance and low latency file transfer and sharing services without complex network configuration, making it suitable for office, home network, and other scenarios.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/993/0*3r4ktgCiw5Tw2-Cw.png" /></figure><p>In practice, for cross-regional collaboration and the popularity of remote work, accessing shared resources over the Internet is often necessary. Security becomes a primary challenge when transmitting data over the Internet, with risks like data interception and man-in-the-middle attacks. Although SMB 3.0 supports encrypted data transmission, it requires upgrading the server and client to support SMB 3.0 and complex encryption configuration.</p><p>This article introduces an alternative solution: using ZTM to transmit SMB protocol data (hereinafter referred to as SMB via ZTM) to achieve secure remote access. This solution has the following advantages over SMB 3.0 encrypted transmission:</p><ul><li>Simplified configuration process without upgrading existing clients and servers.</li><li>Unified encryption and authentication, simplifying management and enhancing security.</li><li>SMB services that originally did not use authentication can enhance security through ZTM’s secure authentication.</li><li>Improved transmission efficiency, reducing network latency and jitter.</li><li>Suitable for remote work and cross-regional access, enhancing flexibility and compatibility.</li></ul><h3>About ZTM</h3><p><a href="https://github.com/flomesh-io/ztm">ZTM</a> (Zero Trust Mesh) is an open-source network infrastructure software. It is built on HTTP/2 tunnels and can run on any type of IP network, such as LAN, containerized networks, and the Internet.</p><blockquote><em>ZTM can be used in various environments, from a 2-node personal network connecting home and workplace to a 10,000-node enterprise network connecting global offices and branches.</em></blockquote><blockquote><em>ZTM supports multiple CPU architectures like x86, ARM, MIPS, RISC-V, LoongArch, and various operating systems like Linux, Windows, macOS, FreeBSD, Android.</em></blockquote><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*5juGdi4FRdEbvrZ_.png" /></figure><p>ZTM includes several core components:</p><ul><li><strong>Traffic Forwarder ZTM Agent</strong>: Deployed in networks that need connectivity. It can be installed on personal computers, servers, edge, or endpoint devices. It connects to the ZTM Hub, initiates encrypted tunnels, and securely forwards the device’s traffic to the Hub.</li><li><strong>Traffic Forwarding Cluster ZTM Hub</strong>: Establishes encrypted tunnels with each Agent, forwarding requests from Agents to achieve multi-point access and high availability.</li><li><strong>Certificate Management Server ZTM CA</strong>: Manages certificates. It issues certificates, revokes certificates, and verifies the TLS certificates used by Agents for access.</li></ul><h3>Solution</h3><p>When implementing ZTM, follow these steps. Steps 1, 2, and 3 are for infrastructure setup. Each network that needs to connect to the Hub must perform steps 2 and 3. Once connected to the Hub, repeat steps 4 and 5 as needed:</p><ol><li>Set up the ZTM Hub.</li><li>Issue certificates for Agents.</li><li>Deploy Agents and connect to the Hub.</li><li>Register services.</li><li>Map services to the local network.</li></ol><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*D5IMYv1Ub7QwZmle.png" /></figure><p>In this SMB via ZTM solution, install ZTM Agent in the networks where the SMB client and server are located. The Agents establish encrypted HTTP/2 tunnels with the ZTM Hub in the public cloud.</p><p>The Agent on the server side registers the SMB service to the Hub; the Agent on the client side maps the service from the Hub to a local port, providing SMB services to the local LAN clients (in the demonstration below, we will install the Agent on the device where the SMB client is located).</p><p>You will notice that the encrypted tunnel is initiated by the Agent, and the SMB service is not directly exposed to the Internet. Even if the SMB service itself does not have authentication capabilities, access via the client-side Agent still requires strong authentication using certificates.</p><h3>Demonstration</h3><p>In the demonstration, we will use a cloud host with a public IP, which can be purchased from cloud providers for 99 yuan, usually with 3–4M bandwidth, sufficient for forwarding 1080P or even low bitrate 4K.</p><p>The SMB service runs in my home network, while my computer is connected to a public network.</p><h3>1. Run ZTM Hub</h3><p>First, SSH into the cloud host and install ZTM CA and Hub using the ZTM CLI. The latest version of ZTM is 0.0.3. Install the CLI with the following command.</p><pre>ZTM_VERSION=0.0.3</pre><pre>curl -sL <a href="https://github.com/flomesh-io/ztm/releases/download/v${ZTM_VERSION}/ztm-aio-v${ZTM_VERSION}-generic_linux-x86_64.tar.gz">https://github.com/flomesh-io/ztm/releases/download/v${ZTM_VERSION}/ztm-aio-v${ZTM_VERSION}-generic_linux-x86_64.tar.gz</a> | tar -zxf -<br />sudo cp bin/ztm /usr/local/bin/ztm</pre><p>Use the command ztm help to view CLI usage.</p><p>Start the ZTM CA service with the following command.</p><pre>sudo ztm start ca --listen 127.0.0.1:9999</pre><p>Next, start the Hub. By default, it listens on port 8888. You can modify this with the --listen parameter. We use the default value here.</p><pre>sudo ztm start hub</pre><h3>2. Issue Certificates for Agents</h3><p><strong>Note: The JSON file contains the public and private keys. Please keep them safe. If lost, revoke the certificate using </strong><strong>ztm evict USERNAME and issue a new certificate.</strong></p><pre>ztm invite home --bootstrap 13.229.223.113:8888 --output &gt; home.json<br />ztm invite macbook --bootstrap 13.229.223.113:8888 --output &gt; macbook.json</pre><h3>3. Deploy Agent on the SMB Server Side</h3><p>Install the Agent on an Ubuntu virtual machine in my Homelab. Install the CLI first, then start the Agent using the CLI. By default, it listens on 127.0.0.1:7777, which can be modified with the --listen parameter to 0.0.0.0:7777.</p><pre>sudo ztm start agent --listen 0.0.0.0:7777</pre><p>This command configures the Agent as a system service. You can check its status with systemctl status ztm-agent.</p><h3>4. Connect Agent to Hub</h3><p>After starting the Agent, the most crucial step is to connect it to the ZTM Hub. There are two methods: command line and web interface.</p><h4>Method 1: Using Command Line</h4><p>In the command line window, run the following command to establish a secure tunnel with the Hub. The command format is ztm join MESH_NAME --as AGENT_NAME --permit JSON_FILE.</p><pre>ztm join my-hub --as smb-server --permit home.json</pre><p>Check the tunnel status with the command ztm get mesh.</p><pre>ztm get mesh<br />NAME    JOINED AS   USER  HUBS                 STATUS<br />my-hub  smb-server  home  13.229.223.113:8888  Connected</pre><p><strong>Note: Use </strong><strong>ztm left MESH_NAME to disconnect from the Hub.</strong></p><h4>Method 2: Using Web Interface</h4><p>Open the web interface at http://&lt;VM IP&gt;:7777.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*1AbB6oiQ9UgYKjd8.png" /></figure><p>In the <strong>Meshes</strong> tab, click <strong>Join</strong>.</p><p>Fill in the information and click Save:</p><ul><li><strong>Mesh</strong>: Enter your desired name, such as my-hub.</li><li><strong>Permit</strong>: Click <strong>+</strong> to select the previously issued home.json.</li><li><strong>Join AS</strong>: Enter your desired name, such as smb-server.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*lxqEhHrw-FQyd8Zx.png" /></figure><p>After saving, you can see the added Hub and its status in the <strong>Meshes</strong> tab. If the status is not <strong>Connected</strong>, check the contents of the issued JSON file.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*aiMBdRnNmRaO3bDX.png" /></figure><p><strong>Note: Click the three dots on the right of the Hub to modify or disconnect it.</strong></p><h3>5. Register Service</h3><p>To access the SMB service from outside, register the SMB service to the Hub on the Agent. This can be done using the command line or web interface.</p><h4>Method 1: Using Command Line</h4><p>The command format is ztm create service PROTOCOL/SERVICE_NAME --host SERVICE_IP --port SERVICE_PORT. Here, we use the existing SMB service, <em>default port 445.</em></p><pre>ztm create service tcp/smb-server --host 192.168.11.104 --port 445</pre><p>Check the registered services with the command ztm get service.</p><pre>ztm get service<br />NAME            ENDPOINTS<br />tcp/smb-server  1</pre><p><strong>Note: Use </strong><strong>ztm delete service PROTOCOL/SERVICE_NAME to unregister the service.</strong></p><h4>Method 2: Using Web Interface</h4><p>In the <strong>Services</strong> tab, click <strong>Create</strong>.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*2Um4QV6LrU3P4Zcr.png" /></figure><p>Fill in the service information and click <strong>Save</strong>:</p><ul><li><strong>Service</strong>: Service name, such as smb-server.</li><li><strong>Protocol</strong>: Select the protocol corresponding to the service, TCP.</li><li><strong>Host</strong>: Service address, here it is the SMB service address 192.168.11.104.</li><li><strong>Port</strong>: Service port, here it is 445.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*LWvkm4GH5emmADM3.png" /></figure><p>After saving, you can see the created service in the <strong>Services</strong> tab.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*evyEXJ6Xkf-D1lL5.png" /></figure><h3>6. Deploy Agent on the SMB Client Side</h3><p>First, install ZTM. You can download the corresponding platform CLI from <a href="https://github.com/flomesh-io/ztm/releases/tag/v0.0.3">here</a>. There are CLIs for x86 and M chips on macOS and exe downloads for Windows.</p><p>My external device is a MacBook, so I download the arm64 CLI.</p><pre>curl -sL https://github.com/flomesh-io/ztm/releases/download/v0.0.3/ztm-aio-v0.0.3-macos-arm64.tar.gz | tar -zxf -<br />sudo cp bin/ztm /usr/local/bin/ztm</pre><p>After installing the CLI, start the Agent with the following command. It will automatically join the system service.</p><pre>sudo ztm start agent</pre><h3>7. Connect Agent to Hub</h3><p>Repeat the same steps, using the previously issued certificate macbook.json to establish a tunnel with the Hub. You can use the command line or web interface (<a href="http://localhost:7777/">http://localhost:7777</a>). Here, we use the command line to complete it. For web interface operations, refer to previous steps.</p><pre>ztm join my-hub --as macbook --permit macbook.json</pre><p>Check the tunnel status.</p><pre>ztm get mesh<br />NAME    JOINED AS  USER     HUBS                 STATUS<br />my-hub  macbook    macbook  13.229.223.113:8888  Connected</pre><h3>8. Map Service to Local</h3><p>Service mapping can also be done in two ways: command line and web interface.</p><h4>Method 1: Using Command Line</h4><p>Use the following command to view registered services on the Hub.</p><pre>ztm get service<br />NAME            ENDPOINTS<br />tcp/smb-server  1</pre><p>Service mapping is done by creating a local port. The format is ztm create port LAN_IP/PROTOCOL/PORT --service PROTOCOL/NAME.</p><pre>ztm create port 127.0.0.1/tcp/1445 --service tcp/smb-server</pre><p>Check the created port.</p><pre>ztm get port<br />NAME                ENDPOINT  SERVICE<br />127.0.0.1/tcp/1445  macbook   tcp/smb-server</pre><p><strong>Note: Use </strong><strong>ztm delete port LAN_IP/PROTOCOL/PORT to delete the port.</strong></p><h4>Method 2: Using Web Interface</h4><p>In the <strong>Services</strong> tab, find the discovered service and click the button in the upper right corner.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*eSkJ3ksLgwfMsIja.png" /></figure><p>Enter the port information in the popup window.</p><ul><li><strong>IP</strong>: Service mapping address. If only accessed by the current device, select 127.0.0.1. If accessible to other devices in the LAN, enter the current device’s LAN address.</li><li><strong>Port</strong>: Service mapping port, which cannot conflict with other ports. Here we map the smb-server service to port 1445.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*wwXBwim6Y-SI1XUC.png" /></figure><p>In the <strong>Local Ports</strong> tab, you can see the created local port.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*a1-bX9wPZkQn-5UZ.png" /></figure><h3>9. Testing</h3><p>In macOS, open Finder, select <strong>Go -&gt; Connect to Server…</strong> from the menu. Enter smb://127.0.0.1:1445/nvme11 in the popup. /nvme11 is my SMB service directory name.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/972/0*jjwlOpQLIaqV-gmT.png" /></figure><p>Click <strong>Connect</strong>, and you will see the connected SMB service in the Finder sidebar. Viewing its information shows the network address.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*VbVfdBmo_bvKitft.png" /></figure><p>You can now manage the remote SMB service like a local file system.</p><h3>Conclusion</h3><p>Transmitting SMB protocol data in a ZTM environment is a simpler, more efficient, and secure solution, especially suitable for scenarios requiring data transmission over wide area networks or untrusted networks. This method not only enhances the security of the original SMB service but also simplifies the complexity of management and deployment.</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=e8fb1c292096" width="1" /><hr /><p><a href="https://blog.flomesh.io/securely-access-smb-shared-files-across-the-internet-using-ztm-e8fb1c292096">Securely access SMB shared files across the Internet using ZTM</a> was originally published in <a href="https://blog.flomesh.io">Flomesh</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
